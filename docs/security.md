# Forge 위협 모델과 설치 전 점검 (TASK-0013)

이 문서는 Forge(스킬·MCP·도구·이력 관리 평면)의 **위협 모델**, 각 위협의 **완화책(구현 위치와 테스트)**, **남은 위험과 알려진 한계**, 그리고 **사용자가 해야 할 일**을 적는다. 모든 문장은 코드·테스트와 대조했고, 코드로 확인하지 못한 것은 "미검증" 으로 적었다. Forge 는 **샌드박스가 아니다**: 사용자가 등록·승인한 명령은 사용자 권한으로 실행된다. Forge 가 하는 일은 (1) 실행 전에 무엇이 실행될지 보여 주고, (2) 바뀌면 알리고, (3) 위험한 경로를 기본으로 막고, (4) 비밀을 저장·출력하지 않는 것이다.

관련 문서: `docs/gateway.md`(게이트웨이·confirm·프록시), `docs/sync.md`(설정 파일 쓰기), `docs/doctor.md`(읽기 전용 점검), `docs/adapter.md`, `docs/clients/*.md`.

## 1. 자산

| 자산 | 어디에 있나 | 왜 중요한가 |
|------|-------------|-------------|
| 사용자 설정 파일 | `<repo>/.mcp.json`, `.claude/settings.json`, `opencode.json`, `~/.claude/settings.json` 등 sync 대상 | 클라이언트가 읽어 **명령(MCP command, hook)을 실행**하는 파일. 바뀌면 임의 실행으로 이어진다 |
| 비밀 값 | 사용자 환경변수, `~/.claude.json`, OpenCode 인증·서비스 파일 | API 키, 토큰. Forge 는 값을 저장하지 않고 `${ENV}` 참조만 둔다 |
| 레지스트리·이력 | `$FORGE_HOME`(기본 `~/.forge`)의 `forge.db`, `skills/<이름>@<버전>/`, `backups/`, `tmp/` | 스킬 본문(모델이 따르는 지침), MCP 명령·도구 정의, 호출 이력. 변조되면 이후 모든 sync·게이트웨이 출력이 오염된다 |
| 사용자 홈 | `~` 아래 그 밖의 파일 | 악성 도구·스킬·서버가 읽거나 지우면 안 되는 개인 파일 |

## 2. 신뢰 경계

| 주체 | 신뢰 수준 | 비고 |
|------|-----------|------|
| 사용자(로컬 셸의 본인) | 신뢰 | 명령 실행·등록·승인 권한이 있다. `FORGE_HOME` 에 쓸 수 있는 사람(같은 사용자의 다른 프로세스 포함)은 레지스트리를 임의로 바꿀 수 있다 — **DB 쓰기 권한자는 방어 대상이 아니다**(5.3 참조) |
| 모델·에이전트 | **비신뢰 입력 생성자** | 모델이 만든 인자는 데이터 위치에만 들어가고(셸 해석 없음) 스키마 검증을 거친다. 모델이 읽는 텍스트(스킬 본문, MCP 도구 설명)는 모델을 조종하려는 입력일 수 있다 |
| 외부 소스(스킬 git/zip, MCP 서버 패키지, 원격 MCP URL) | **비신뢰** | 설치 전 미리보기·승인·해시 고정의 대상. 가져오기 단계(압축 해제·git 클론)부터 방어한다 |
| 클라이언트(Claude Code, OpenCode) | 부분 신뢰 | Forge 는 클라이언트가 설정 파일을 어떻게 읽고 무엇을 실행하는지 **검증하지 못했다**(실클라이언트 로드는 미검증, TASK-0020 AC-5) |
| 악의적 저장소(내가 연 프로젝트 디렉터리) | **비신뢰** | 그 안의 `.mcp.json`, `.claude/`, `opencode.json`, 스킬 디렉터리, 심볼릭 링크·하드링크, 위조된 상태 파일이 공격 수단이 된다 |

## 4. 알려진 한계 (과장 없이)

- **실제 Claude Code·OpenCode 로드는 검증하지 않았다.** 생성한 설정을 클라이언트가 실제로 읽는지, 게이트웨이 `clientInfo.name`, elicitation 지원 여부, 도구 이름 64자 한도, 스킬 frontmatter `hooks` 를 클라이언트가 실제로 어떻게 처리하는지는 문서·가짜 클라이언트 기준이다(TASK-0020 AC-5). Linux·Windows 도 검증하지 않았다(검증은 macOS).
- **deny 목록은 샌드박스가 아니다.** 커스텀 도구 보호는 심층 방어일 뿐이다. 코드 실행형 바이너리는 이름 기반 휴리스틱으로 분류해 확인(ask)을 강제하지만(TASK-0018) 분류 밖의 이름·래퍼·이름을 바꾼 복사본은 놓친다. 위협 모델과 알려진 한계는 "도구 실행 위협 모델과 code-exec 분류 (TASK-0018)" 절. MCP 서버·스킬 스크립트·클라이언트가 실행하는 모든 것은 사용자 권한으로 실행된다.
- **미리보기의 위험 패턴은 휴리스틱**이다. 본문의 의미적 인젝션, 난독화된 명령, 스크립트·참조 파일 내용은 탐지하지 못한다.
- **승인은 "내가 본 내용" 에 대한 것**이다. 해시 고정은 같은 내용임을 보장할 뿐 안전을 보장하지 않는다. MCP 도구 정의 승인은 refresh 로 캐시된 정의에 대한 것이며, 서버 동작(같은 정의 아래의 구현)은 알 수 없다.
- **`enforce` 는 게이트웨이 경유 노출에만** 적용되고 기본은 꺼져 있다. 변경 탐지는 `refresh` 시점에만 일어난다.
- **클라이언트 `--version` 실행의 한계**: 검사와 실행 사이의 교체(TOCTOU)는 막지 못하고, 확인 도중 forge 가 `SIGKILL` 로 죽으면 `TMPDIR` 에 `forge-ver-<pid>-<난수>` 임시 디렉터리가 남을 수 있다(다음 실행이 소유자·접두사·죽은 pid·1시간 경과를 모두 만족하는 정확한 경로만 지운다; PID 없는 예전 이름은 건드리지 않음, TASK-0032 AC-4). 세부와 PATH 정책의 그 밖의 한계는 `docs/doctor.md` 의 "후속 보강과 알려진 한계".
- **DB 쓰기 권한자는 방어 대상이 아니다.** `forge.db`·`~/.forge` 에 쓸 수 있으면 해시·승인 기록·정책을 함께 바꿀 수 있다. 파일 권한(0600/0700)과 OS 계정 경계에 의존한다.
- **elicitation 미지원 클라이언트에서 `confirm=ask` 도구는 항상 거부**된다(안전 쪽). 기본값 결정은 후속(TASK-0020).
- **휴리스틱 마스킹의 한계**: 비밀스럽지 않은 이름의 짧은 값은 가려지지 않을 수 있다(TASK-0017, 0019, 0020). **키 이름 정규화(TASK-0019)**: 신규 의존성(`x/text` NFKC)은 도입하지 않고 표준 라이브러리만 쓴다. ledger payload 의 JSON 키는 비밀 단어 검사 전에 결합 문자(Mn) 제거, 구분자(`-` `_` 공백 `.` 와 유니코드 Pd 대시·마이너스, Pc 연결 문자, Zs 공백(NBSP 등), Cf 서식·제로폭 문자 범주 전체) 제거, 소문자화, 키릴·그리스 대표 동형문자 소규모 표 접기를 거친다(`pass-word`, `pass_word`, 결합 악센트, 키릴 a 변형이 가려진다. 테스트 `TestMaskKeyAndInlineHardening`). **한계**: 표에 없는 동형문자(예: U+04CF)와 NFKC 전체 호환 분해는 접히지 않는다. 배열 안의 `--token` 형 플래그 요소에는 `foldKey` 만 적용되어 동형문자·결합 문자 변형 플래그는 놓칠 수 있다. 값이 비밀처럼 보이지 않으면 통과한다. 값 쪽 패턴 규칙은 그대로 동작한다. 등록한 `--env KEY=${ENV}` 비밀의 base64·URL 인코딩 에코는 게이트웨이·refresh·도구 출력에서 가려지지만, ledger·diff 의 패턴 마스킹과 비밀 안에 일부만 든 인코딩은 못 가린다(아래 "MCP 등록 후속").
- **이력 마스킹 보강과 남는 한계(TASK-0021, ledger 마스킹 규칙 버전 4)**: 라벨 없는 `sk-…`(20자 이상)·`ghp_/gho_/ghu_/ghs_/ghr_…`·`github_pat_…`·JWT(`eyJ….….…`)·AWS 액세스 키 ID(`AKIA/ASIA`+16자)·`Bearer <토큰>`, 따옴표로 묶인 값(`api_key = "a b"`), `-p <값>`, 대문자 환경변수 형태의 값(`TOKEN=ab cd`: 따옴표·`&`·`;`·`,`·줄 끝까지 전부)을 이제 마스킹한다(테스트 `TestMaskInlineFollowups`, `TestMaskInlineLeavesOrdinaryText`, `TestMaskPayloadCoversFollowups`). **한계**: `-p 22` 처럼 비밀이 아닌 `-p` 값도 가려진다(표시용 과마스킹 선택). `mkdir -p a/b`·`ls -p dir`·`cp -p src dst` 같은 흔한 명령의 인자와, 이름에 TOKEN 이 든 `TOKEN_COUNT=3` 같은 비비밀 환경변수 값도 가려진다. 20자 미만의 `sk-` 값, 소문자 변수명의 공백 포함 값(`token=ab cd` 는 `ab` 만 가려진다), 라벨이 없는 임의 문자열은 못 가린다.
- **이력 마스킹 보강 2(TASK-0020 AC-2, ledger 규칙 버전 5)**: 값 안의 이스케이프된 따옴표(`api_key="a\"b"`), 문자열 속 JSON 텍스트와 셸 줄의 이스케이프된 따옴표 값(`{\"api_key\":\"x\"}`, `export API_KEY=\"x\"`), 따옴표가 붙은 키, 전각·결합 기호·제로폭·키릴/그리스 비슷한 문자로 쓴 라벨(`ｔoken=...`)을 가린다(`maskFoldedLabels`: 접은 텍스트에서 찾은 값 구간만 원문에서 `***` 로 바꾸고 나머지는 그대로 둔다). 테스트: `TestMaskInlineTask20Limits`, `TestMaskInlineKeepsOriginalCharacters`. 남는 한계: confusables 표에 없는 글자, 따옴표를 쪼갠 값, 비밀스러운 이름이 없는 짧은 값. 같은 TASK 의 `forge ... --json` 출력은 구조·값을 유지한 채 ESC·U+202E 등 터미널이 해석하는 문자를 JSON 유니코드 이스케이프로 바꿔 쓰고(`writeJSON`), `forge mcp show` 사람용 출력은 도구 설명뿐 아니라 서버 정보·오류·값 이름·경로까지 `textsafe.Display` 로 이스케이프한다(`TestMCPShowEscapesEveryStoredText`).
- **hook·게이트웨이 이중 집계 연결과 이력 읽기 한계(TASK-0021, ADR-F0003)**: 같은 호출을 hook 과 게이트웨이가 각각 기록하면 나중 행이 짝을 찾아(같은 등록 client, 대응하는 이름, 5초 이내, 1:1) 같은 키로 만든다(테스트 `TestLinkHookThenGatewayCustomTool`, `TestLinkIsOneToOneAndNearestWins`, `TestLinkRefusals`). **직접 병합(TASK-0030, ADR-F0004)**: Claude Code 가 `tools/call` 의 `params._meta["claudecode/toolUseId"]` 로 보낸 값이 안전하면(`[A-Za-z0-9_-]` 1~128바이트, claude-code client 만) 게이트웨이 행의 `tool_use_id` 가 되고 hook 행과 그 id 로 직접 병합된다(같은 client·대응하는 이름·1:1, 시간 창 없음; id 가 다르면 5초 안이어도 합치지 않는다; 테스트 `TestDirectMerge*`). 값이 없거나 이상하면 무시하고 시간 창 연결이 폴백이다. 같은 id 를 재사용하는 호출(비정상)은 이미 병합된 게이트웨이 행을 갱신할 뿐 새 행을 만들지 않는다. **같은 세션의 동일 `/스킬명` 반복 입력은 `tool_use_id` 가 없어 각각 별개 행이다**(UserPromptExpansion 은 id 를 주지 않으며 의도된 동작). **연결하지 못하면 이중 집계(과대 집계)로 남는다**: 메타 도구(`forge_skill`·`forge_list`), 게이트웨이가 이름을 줄이거나 해시를 붙인 도구, PreToolUse hook 없이 5초보다 긴 호출, client 미등록 행, 이전에 기록된 행(소급 연결 없음). 같은 도구를 5초 안에 병렬 호출하면 호출 수는 맞지만 ok·지연 값이 엇갈려 귀속될 수 있다. **오탐 경로**: 게이트웨이에 닿지 않고 차단된 호출의 hook 행(예: 다른 hook 이 거부)이 있는데 1초 뒤 같은 이름의 다른 호출이 게이트웨이에 기록되면 둘이 한 호출로 합쳐질 수 있다(5초 안, 같은 client·같은 이름). 이 경우 실제로는 2건인데 1건으로 센다(과소 집계). 병합된 호출의 성공 여부는 **실패 우선**이다(한 source 라도 실패면 실패, 마이그레이션 0004, 테스트 `TestMergedOKIsFailureFirst`). `forge history` 는 WAL DB 를 `mode=ro` + `query_only` 로 열며(각각 단독 시험 `TestReadOnlyDefensesEachStandAlone`) 이때 SQLite 가 빈 `forge.db-wal`/`-shm` 을 만들 수 있고 닫은 뒤에도 남는다(DB 내용은 불변). 위치가 읽기 전용이라 열 수 없으면 `immutable` 로 한 번 재시도하고 알림을 출력한다(WAL 에 남은 최신 기록은 안 보일 수 있다, 테스트 `TestOpenReadOnlyDirectoryFallsBackToImmutable`). `--output` 은 `-` 이면 표준 출력이고, 부모 디렉터리가 심볼릭 링크면 따라가며(사용자가 고른 경로) 마지막 구성요소가 심볼릭 링크이거나 Forge 저장소 파일이면 거부한다(`TestWriteFileFollowsParentSymlinkButNotTheFinalOne`). 기간 없는 `summary`/`top` 은 원장 전체를 집계해 1M 행에서 약 4초(행 수에 비례)이므로 50만 행 이상이면 `--since` 를 권하는 알림을 stderr 로 낸다(집계 테이블·캐시는 도입하지 않았다). 1M 행 시험은 `FORGE_LARGE_TESTS=1` 일 때만 실행한다.
- **사용자 `/스킬명` 기록(TASK-0028)**: `UserPromptExpansion` hook 은 등록된 스킬 이름·시각·session_id·client·project 만 남기고 `command_args`·`prompt` 는 디코드조차 하지 않는다(길이 등 파생 값도 없음, `record_payload=1` 이어도 payload 행 없음). 미등록·내장 명령은 기록하지 않는다. 테스트 `TestUserPromptExpansionNoPromptOrArgs`.

예외 규칙과 자체 공격 평가:

- **라벨 예외**: 키/플래그 이름의 마지막 단어가 commit/rev/ref/sha/sha1/sha256/hash/digest/checksum 이고 값이 정확히 40·64자 hex 이거나 `sha256:<64hex>` 일 때만. 32자·그 외 길이·무라벨 hex·`COMMIT_TOKEN` 같은 비밀 단어 키는 계속 거부.
- **식별자 예외**: `_`·`-` 로 나눈 3개 이상, 2~12자 소문자 단어(모음 있고 자음 4연속 없음) 3개 이상. **숫자는 마지막 부분의 버전 꼴(`v2`, `2024`, `rc1`)이거나 마지막 단어 바로 앞의 `v<N>`(`..._v2_final`)에만** 허용하고, 그 밖의 위치에 숫자가 섞이면 식별자로 보지 않는다(단어에 숫자를 섞은 암호문구는 거부).
- 32자 이상 hex(철자·숫자 혼합)는 엔트로피와 무관하게 비밀로 본다. 40자 base64 모양(AWS 비밀 키 형태)도 잡는다.
- 코퍼스(`internal/mcp/secretcorpus`, 시드 고정 가짜 값)에서 **예외로 새로 통과하는 가짜 비밀은 0건**이고, 아래 잔여 위험은 코퍼스에서 따로 집계해 시험으로 고정했다(`TestResidualRisksOfTheExceptions`).

**잔여 위험(미탐 가능성, 등록 맥락)** — 미탐이 0 이라는 뜻이 아니다. 정직하게 적는다:

1. **경로 구성요소의 접두 없는 비밀은 통과**한다. 대상은 알려진 루트 31개(`Users home var private tmp opt usr etc Library Applications System Volumes mnt srv root proc dev run nix snap bin sbin lib lib64 cache data workspace app src build work`) 아래뿐 아니라 `~/`, `./`, `../`, `node_modules/`, 드라이브(`C:\`, `D:/`) 아래도 포함한다. 독립 시험에서 `/tmp/<무작위 40자>` 는 3000/3000 통과했다. 루트 집합이 넓어 사실상 대부분의 실제 절대 경로가 해당한다. **영구 저장 데이터(ledger payload)는 엄격 모드라 이런 값도 가려진다.**
2. **라벨 위장**: `commit=<API 키 40자 hex>`, `--ref <hex>`, `GIT_COMMIT=<64자 hex>`, `sha256:<64자 hex>`, `my-sha=<hex>`, `--api-hash <hex>`, `digest=<hex>`, `--sha256 <hex>` 처럼 라벨이 붙은 40·64자 hex 비밀은 통과한다.
3. **단어형 암호문구**: 숫자 없는 단어 암호문구(`correct-horse-battery-staple`)는 원래부터 통과한다. 여기에 **끝 숫자를 붙인 암호문구(`a-b-c-d-1234`)도 약 99% 통과**한다(독립 시험 1981/2000). `release-2024`·`image-name-2024` 같은 정상 식별자와 구별할 수 없어 택한 절충이다. 중간 숫자나 단어 안에 섞인 숫자는 거부한다(수정 전 수준). 발음 가능한 합성 토큰도 구별되지 않는다.
4. **짧은 접두를 앞 글자에 붙이면 통과**한다: `sk-`, `npm_`, `hf_`, `SG.`, `ya29.`, `eyJ`, `AIza`, `AKIA` 는 경계(구성요소 시작 또는 `._-/:=@` 뒤)에서만 본다. 이는 `pnpm_store`, `risk-model`, `task-runner` 같은 정상 이름을 거부하지 않으려는 의도된 설계다. 긴 고유 접두(`github_pat_`, `whsec_`, `sk_live_`, `prefixghp_...` 의 `ghp_`+긴 꼬리 등)는 구성요소 중간에서도 거부한다.
5. **40자 base64 규칙의 한계**: 정확히 40자이고 `/` 또는 `+` 를 포함하며 엔트로피 4.0 이상인 값만 잡는다(AWS 비밀 키 모양). 이 규칙은 등록 맥락 기준이며, 저장 맥락에서도 가려지지 않는 경우가 있다(HEAD 와 같은 기존 한계, 독립 시험 6건). 다른 길이의 base64 키, 접두 없는 24자 미만 키도 원래부터 못 잡는다.
6. **좁은 범위**: HTTP body 템플릿·스크립트 본문·JSON 텍스트처럼 경로가 공백으로 구분된 독립 필드가 아니라 따옴표·`":"` 로 붙어 있으면(`{"p":"/tmp/..."}`, `--out="/x"`) 경로 예외가 적용되지 않는다. 오탐이 늘 뿐 미탐은 늘지 않는다.
7. **남은 오탐(안전한 쪽)**: 집합 밖 루트의 정상 파일 경로(`/mydata/<무작위>/...`), 공백이 든 경로(`/Library/Application Support/<24자>/...`, 독립 시험 10건)는 계속 거부된다. `git+https://...#<sha>` 는 URL 엄격 정책상 의도된 거부다(6건).

**독립 측정 요약**(Verifier 코퍼스: 가짜 비밀 340·정상 386, 고정 시드): 인자 재현율 HEAD 95.3% → 95.6%, 정밀도 62.3% → 95.3%, 정상 오탐 196 → 16, 저장 맥락 재현율 98.2%, 순수 무작위 약 5.5만 개 중 새로 통과한 것 0건. 재현율이 100% 가 아닌 것은 위 잔여 위험 때문이다.

- **사용자 안내**: 경로·식별자에 비밀을 넣지 말고 비밀은 항상 `--env KEY='${ENV_NAME}'`·`--header 'Authorization=${ENV_NAME}'` 참조로 넣는다. 인자로만 받는 서버는 환경변수를 읽어 실행하는 래퍼 스크립트를 등록한다.

### MCP 등록 후속 (TASK-0017)

**1. stdio 인자의 `${ENV}`** — `forge mcp add ... -- node s.js --root=${ROOT}` 는 **등록된다**(이전과 같다. Claude Code 가 args 의 `${VAR}` 를 확장하므로 거부는 과하다) 대신 미리보기(`--preview` 포함)에 **경고**가 나온다(`mcp.ArgRefIndex`, `internal/mcp/preview.go`). 이유: Forge(`refresh`·게이트웨이)는 `exec.Command` 로 인자를 그대로 넘기므로 서버는 글자 그대로 `${ROOT}` 를 받는다. 반면 Claude Code 는 `command, args, env, url, headers` 의 `${VAR}` 를 확장하고(`docs/clients/claude-code.md` 의 env/헤더 행, [doc]) 직접 노출하면 확장되지만, OpenCode 는 `{env:VAR}`·`{file:path}` 문법이라 직접 노출은 sync 에서 거부된다(`SubstInCommand`, `docs/clients/opencode.md` [doc]·[bin]). 같은 등록이 경로에 따라 다르게 동작한다. 경고는 인자 번호만 보여 주고 값·기본값은 싣지 않으며 `{env:}`·`{file:}` 도 같이 본다. 권장: `--env KEY='${ENV_NAME}'` 로 넘기고 서버가 환경변수에서 읽게 하거나 환경변수를 읽어 실행하는 래퍼 스크립트를 command 로 등록한다. `sh -c '<스크립트>'` 류는 셸이 직접 확장하므로 경고하지 않는다. `--strict` 는 모든 등록에 승인을 요구하는 기존 동작 그대로다(경고 여부와 무관). 이 점검은 **등록 시점에만** 있고 `Spec.Validate`(sync 렌더 재검증)에는 없어 이미 등록된 서버의 렌더링은 바뀌지 않는다. **`forge tool add` 는 거부한다**: Forge 가 도구를 셸 없이 직접 실행하고 `${...}` 를 확장하지 않으므로 프로그램이 글자 그대로 받는다(argv 번호는 다른 도구 메시지와 같은 `argv #N`, shell 도구는 제외). 이것도 등록 시점(`ValidateNew`)에만 있고, 이전 버전이 저장한 도구 행은 그대로 해석·실행된다. 테스트: `TestEnvRefInArgsRegistersWithWarning`, `TestMCPAddWarnsOnEnvRefInArgs`, `TestCommandToolRefusesEnvRefInArgv`, `TestStoredToolWithEnvRefInArgvStillRuns`.

**3. 마스킹과 인코딩 에코, 줄 상한** — (a) 검토 결과: `--env KEY=${ENV}` 로 해석된 비밀은 값 그대로만 치환했고 base64·URL 인코딩 에코는 가려지지 않았다. 이제 `mcp.SecretForms` 가 비밀과 표준·URL-safe base64(패딩 유무 4종)·URL 쿼리/경로 이스케이프를 합쳐 **비밀당 최대 7개 문자열**만 치환 목록에 넣는다(비용 한정. 8바이트 미만 비밀은 인코딩 형태가 정상 텍스트와 겹칠 수 있어 값 그대로만). 적용 범위: refresh 캐시(`maskDiscovered`)·진단 메시지·게이트웨이 응답·`forge tool` 출력(`masker`). 중복이던 치환 루프 3개는 `maskText` 하나로 모았다(순서가 비결정이던 `sanitize` 도 긴 값 먼저로 통일). **가리지 못하는 것**: 비밀이 더 긴 텍스트 안에 섞여 인코딩된 경우(정렬이 달라 전체의 인코딩이 다르다. 예 `base64("user:" + 비밀)`), hex·이중 인코딩·사용자 정의 변환, 환경변수 참조가 아닌 literal 값, 그리고 **비밀 값을 모르는 곳**: ledger 와 `sync --diff` 의 마스킹은 값이 아니라 키 이름·패턴으로 가리므로 인코딩된 에코는 패턴에 걸릴 때만 가려진다. (b) stdio 서버의 한 줄(JSON-RPC 메시지 하나, tools/list 응답 포함)이 4 MiB 를 넘으면 연결을 끊는다. 오류가 이제 서버 이름·상한(4 MiB)·원인(tools/list 응답 등)·대처(도구 설명·스키마를 줄이거나 서버를 나눠 등록)를 한 문장으로 알리고 출력 내용은 싣지 않는다. 테스트: `TestRefreshMasksEncodedEchoesOfResolvedSecret`(refresh 통합), `TestMaskCoversBase64AndURLEscapedEchoes`, `TestMaskerCoversEncodedEchoes`, `TestStdioOversizedLineErrorNamesServerAndLimit`.

**4. 버전 미고정 패키지의 고정 방법** — 경고(`unpinned`·`range`·`tag`) 바로 아래에 `고정 방법:` 한 줄을 더 보여 준다(기본 동작과 `--strict` 는 그대로). 근거가 설치본이 아니라 각 도구의 알려진 문법이므로 버전에 따라 다를 수 있는 것은 "미확인"으로 표시한다.

**결정 필요(사용자)** — 아래 둘은 **구현하지 않았고 기본값은 바꾸지 않았다**. 권고만 적는다.

1. `forge mcp add --strict` 기본값(현재 꺼짐, 질문 없이 등록): **권고 — 기본은 유지**하고, 경고(`warn`)가 있을 때만 승인을 요구하는 중간 단계를 다음 후보로 둔다. 이유: 등록은 서버를 실행하지 않고(`refresh` 가 실행), 기본 질문은 시연·스크립트 호환을 깨며, 경고 없는 등록에는 질문의 이득이 없다. 바꾼다면 비대화형에서 `--yes` 가 없을 때 거부할지 통과시킬지도 함께 정해야 한다.
2. `npx -y` 의 설치 확인 생략: Forge 는 사용자가 준 명령줄을 바꾸지 않는다(바꾸면 서버 동작이 달라진다). **권고 — 지금은 경고만 유지**하고, 다음 단계 후보는 "`-y` + 버전 미고정" 조합에만 승인을 요구하는 것이다. 거부는 권하지 않는다: 클라이언트가 띄우는 stdio 서버에는 터미널이 없어 `-y` 없이는 설치 질문에서 멈출 수 있다(npm 버전별 동작은 **미확인**). 고정 버전(`pkg@1.2.3`)과 함께 쓰는 `-y` 는 매번 다른 코드를 받지 않으므로 경고 수준을 낮추는 것도 검토할 수 있다.

| 도구 **정의**(argv 템플릿, `--shell` 본문, 스크립트, URL, allowlist, 정책) | **신뢰**: 사용자가 `forge tool add` 로 직접 작성·승인 | 정의가 곧 코드다. Forge 는 정의의 악의를 판별하지 않는다. 다만 실수를 줄이려고 등록 시·로드 시·실행 직전에 정책(셸 금지, deny 목록, 프로그램 자리의 변수 금지, 시크릿 평문 금지)을 다시 검사한다 |
| 에이전트(모델)가 준 **인자 값** | **비신뢰** | 값은 스키마로 검증된 뒤 **데이터 위치**(argv[2:] 의 한 요소 안, `FORGE_ARG_*` 환경변수, stdin JSON, URL 경로·쿼리)에만 들어간다. 셸이 해석하지 않고, `-` 로 시작하는 값은 기본 거부, 프로그램·서브커맨드 자리의 변수는 기본 거부(`--allow-var-subcommand`) |
| 도구가 실행하는 **프로그램** | 신뢰(사용자 권한으로 실행) | 프로그램이 *자기 인자*를 코드로 해석하면 데이터가 코드가 된다. 이것이 deny 목록과 code-exec 분류가 다루는 구멍이다 |
| `FORGE_HOME`/`forge.db` 에 쓸 수 있는 주체 | 신뢰 경계 **안**(방어 대상 아님) | 4절의 DB 쓰기 권한자 항목 |

**2. deny 목록은 샌드박스가 아니다.** `internal/tool/denylist.go` 의 목록(env, xargs, find, awk, sed, make, tar, docker, ssh, 셸, python/node 등)은 *allowlist 에 넣은 첫 프로그램이 다른 프로그램을 실행하는 래퍼*인 경우를 등록·로드·실행 직전에 거부하는 **심층 방어**다. 이름(버전·`.exe` 정규화)과 심볼릭 링크 체인의 모든 이름·최종 대상을 본다. 목록은 열거형이라 완전할 수 없고, 목록에 없는 프로그램이 데이터를 코드로 해석하면 우회된다. 그런 프로그램 중 흔한 것은 아래 3항의 `risk=code-exec` 로 별도 분류한다. 프로세스 격리(파일시스템·네트워크·시스콜 제한)는 하지 않는다 — 도구는 사용자 권한으로 실행된다.

**알려진 한계(남는 것, 의도적)**:

- **DB 쓰기 권한자**: `forge.db`·`~/.forge` 에 쓸 수 있으면 정의·정책·승인 기록·`ack_code_exec` 를 바꿀 수 있다. 로드 시 정책 재검사(`Registry.Resolve`)는 *실수·부분 변조*를 잡을 뿐 방어선이 아니다(파일 권한 0600/0700 과 OS 계정 경계에 의존).
- **`--shell` 본문 해시 없음**: `--shell` 도구의 스크립트는 argv 한 요소(`sh -c <본문>`)로 DB 에 저장되고, script 도구와 달리 별도 파일·sha256 무결성 기록이 없다. 본문은 위 DB 한계와 같은 신뢰를 받는다. 본문 `{{변수}}` 는 금지이고 인자는 `$FORGE_ARG_<이름>` 환경변수로만 가지만, 본문이 `eval`·`sh -c "$FORGE_ARG_x"` 처럼 값을 코드로 쓰면 분류·검사가 모른다.
- **TOCTOU**: 경로 해석·deny 검사와 `exec` 사이의 파일 교체는 완전히 막지 못한다. 실행 직전에 PATH 를 다시 풀고 같은 경로·allowlist·deny 목록을 재검사해 창을 줄였다(`runLocal` 의 두 번의 `checkExecutable`; 시험 `TestRunStageRechecksDenyListAfterBinarySwap` 가 세 경우를 시험한다: exec 직전 재검사는 Run 경로에서, 첫 검사는 dry-run 경로에서 각각 단독으로 잡히며 변이로 한쪽씩 제거하면 해당 하위 시험이 실패한다. Run 경로에서는 두 번째 검사가 첫 검사와 중복이라 첫 검사만 지우면 Run 시험은 통과한다 — 첫 검사의 단독 효과는 dry-run 에만 있다). 마지막 검사와 `exec` 호출 사이에 같은 경로의 파일을 바꾸는 경쟁은 남는다.
- **`setsid` 등으로 타임아웃 회피**: 타임아웃은 프로세스 그룹(`Setpgid`)을 죽인다. 자식이 새 세션·새 그룹(`setsid`, 데몬화)을 만들면 그룹 종료에서 벗어날 수 있다. `setsid` 자체는 deny 목록에 있지만 code-exec 프로그램이 같은 일을 할 수 있다. cgroup·샌드박스는 쓰지 않는다.
- **deny 목록·분류는 이름 휴리스틱**: 이름을 바꾼 복사본(링크는 따라가지만 복사본은 모름), 래퍼 스크립트(`./run.sh` 가 `npm` 을 부름), 목록에 없는 바이너리, 서브커맨드가 변수로 정해지는 경우는 놓친다. 목록은 시간이 지나면 낡는다.
- **같은 사용자의 다른 프로세스**: 임시 스크립트·FORGE_HOME 을 같은 사용자가 바꾸는 것은 막지 못한다(0600 임시 사본·0700 디렉터리는 다른 사용자만 막는다).

**3. code-exec 분류(AC-2)**

- **무엇이 code-exec 인가** (`internal/tool/risk.go`, `codeExecExec`): 인자로 받은 코드·스크립트·명령·패키지를 실행하는 프로그램 — `sqlite3`(`.shell`·`.system`), `psql`(백슬래시 `!` 셸 이스케이프), `mysql`·`mariadb`·`mongosh`·`redis-cli`, `npm`·`npx`·`pnpm`·`pnpx`·`yarn`·`bunx`, `uv`·`uvx`·`pipx`·`pip`·`poetry`·`conda`, `bundle`·`gem`·`rake`·`composer`, `swift`·`swiftc`·`java`·`jshell`·`kotlin`·`scala`·`sbt`·`gradle`·`mvn`·`lein`·`dotnet`, `irb`·`ghc`·`runghc`·`ghci`·`julia`·`elixir`·`mix`·`erl`·`dart`·`flutter`·`Rscript`, `open`·`xdg-open`. **서브커맨드로 판정**: `go`(`run generate test install tool get build vet`)·`cargo`(`run test install build bench check script clippy doc fix`) — `go list`·`cargo metadata` 는 아니다. 서브커맨드가 `{{변수}}` 이면 code-exec 로 본다. 이미 deny 목록·셸·인터프리터(python3, node 등)인 이름은 등록 자체가 거부되므로 여기에 없다.
- **판정 방식**: command 도구의 argv[0] 이름(버전·`.exe` 정규화, 심볼릭 링크 체인의 이름 포함)과 리터럴 인자. `--shell` 도구는 본문을 `;`·`&`·`|`·개행·괄호·백틱으로 나눈 각 조각의 첫 단어(앞의 `VAR=x` 제외)를 본다. script/http 도구는 분류하지 않는다(스크립트는 사용자가 쓴 코드이고 인자는 stdin JSON 데이터).
- **데이터 모델**: 저장하지 않는다. `Definition.Risk`(`risk=code-exec`)는 읽을 때(`Registry.Get`·`List`, `Validate`) **파생**한다 — 스키마 변경·마이그레이션 0005 가 필요 없다(`db/schema.sql` 불변). 명시 확인(`ack_code_exec`)만 기존 `settings` 테이블의 `tool.ext.<이름>` JSON 확장에 저장한다(`confirm` 은 기존 `tools.confirm` 컬럼). `forge tool list`·`show --json` 에는 필드가 추가될 뿐(`risk`, `policy.ack_code_exec`) 기존 필드는 그대로다.
- **`forge tool add`**: code-exec 이면 stderr 에 경고를 출력한다(분류 이유, 휴리스틱임, 게이트웨이가 ask 를 강제함). 기본 `confirm` 은 원래 `ask` 이다. **`--confirm none` 은 `--yes-code-exec` 없이는 등록을 거부**한다(오류가 이유와 방법을 설명). `--yes-code-exec` 는 `--confirm none` 일 때만 의미가 있고(그 외는 거부) 등록 시점에만 검사한다(`ValidateNew`; 저장된 행은 로드 시 거부하지 않는다).
- **게이트웨이 강제**(`effectiveConfirm`): code-exec 이고 confirm 이 `none`(또는 빈 값)이며 `ack_code_exec` 가 없으면 `ask` 로 올린다. `forge_list` 설명에 "(실행 전 사용자 확인 필요)" 가 붙고, 승인 메시지에 `위험: "코드 실행형 프로그램 sqlite3 (risk=code-exec) ..."` 줄이 붙는다. elicitation 이 없는 클라이언트에서는 거부되며 안내문이 `--confirm none --yes-code-exec` 를 알려 준다. `deny` 는 그대로 `deny` 다. `forge tool test`(사용자가 직접 실행)는 영향이 없다.
- **명시적 allow 를 어떻게 할 것인가(결정)**: `--yes-code-exec` 로 위험을 확인한 `--confirm none` 은 **허용**한다. 근거: (1) 도구 정의는 사용자 작성 신뢰 입력이고 같은 사용자가 이미 임의 명령을 실행할 수 있어 거부는 보안 이득 없이 불편만 준다 — 필요한 것은 *실수로* 코드 실행형을 무확인으로 두지 않는 것이다. (2) elicitation 을 지원하지 않는 클라이언트(OpenCode 는 미확인)에서 ask 도구는 항상 거부되므로 탈출구가 없으면 도구를 쓸 수 없다. (3) 확인이 기록(`ack_code_exec`)으로 남아 `tool show` 에서 보인다. 한계: 플래그만으로 모델 인자가 안전해지지는 않는다.
- **기존 도구의 호환성(재분류 정책)**: 분류가 파생이라 **업그레이드 즉시 모든 저장된 도구에 적용**된다. 이미 `confirm=none` 으로 등록된 code-exec 도구(예: `sqlite3`)는 **차단·삭제되지 않고** 게이트웨이에서 `ask` 로 확인을 요구받는다(`tool list` 의 CONFIRM 열에 `none->ask(forced)` (ASCII 표기: 한글이 열 정렬을 깨뜨려 바꿈, TASK-0032 AC-8)). 계속 무확인으로 쓰려면 `forge tool add <이름> --replace ... --confirm none --yes-code-exec` 로 한 번 확인한다. 조용히 모두 `ack` 처리(그랜드파더링)하지 않은 이유: 그러면 분류가 기존 도구에 효과가 없어 목적이 사라진다. 확인을 요구하는 쪽이 안전한 기본이다. 영향: elicitation 이 없는 클라이언트에서 기존 무확인 code-exec 도구는 위 재등록 전까지 거부된다. 시험: `TestLegacyCodeExecRowStillResolvesButIsForcedToAsk`.
- **한계**: 위 2항의 이름 휴리스틱 한계가 그대로다. 고정 argv(변수 없음)의 `npm test` 도 code-exec 로 본다(저장소 코드가 바뀔 수 있어 변수 유무로 가르지 않았다). 래퍼 스크립트·복사본·목록 밖 프로그램, 셸 본문의 `eval`·변수 속 프로그램 이름은 놓친다. `go -C d run` 처럼 서브커맨드가 플래그 뒤에 있으면 앞 4개 인자 안에서만 찾는다.

**4. 인자 경로 제한 검토(AC-3) — 결정: path 타입 변수를 도입하지 않는다.**

- **현재 동작**(시험 `TestPathArgumentsAreNotConfinedByDesign`): 작업 디렉터리(`--cwd`·`working_dir`)는 실행 위치만 제한한다. `cat -- {{file}}` 의 값이 절대 경로(`/etc/hosts`)면 그대로 전달된다(cwd 밖 읽기 가능). `git diff {{ref}}` 에 `--output=…` 을 넣는 것은 기본 거부되는 선행 `-` 규칙으로 막힌다(`--allow-dash` 로 풀면 열린다).
- **검토한 안**: 스키마 속성에 `x-forge-path`(또는 `format: path`)를 두고 값을 `Clean` + `EvalSymlinks` 한 뒤 cwd 루트 아래인지 확인.
- **도입하지 않는 이유**: (1) 프로그램마다 인자 해석이 달라(`--output=`, `file:` URL, `~`, 글롭, `-` 로 시작하는 파일, `@file`) 문자열 하나의 경로 검사는 보호하는 것처럼 보이지만 우회된다(거짓 안심이 위험 신호를 가린다). (2) 검사한 경로가 `exec` 시점에도 같다는 보장이 없다(TOCTOU, 심볼릭 링크 교체). (3) 프로그램이 스스로 읽는 파일(설정·include·플러그인)은 막을 수 없다. (4) 실제 요구(특정 디렉터리만 읽기)는 고정 argv·전용 프로그램·script 도구에서 직접 경로를 검증하는 쪽이 더 정확하다. 지금 단계에서는 과대 구현이다.
- **기록하는 한계**: 모델 인자가 경로이면 cwd 밖 파일을 읽거나 쓰는 프로그램 인자가 될 수 있다. 완화는 (a) 읽기 전용 프로그램만 쓰고, (b) 변수 앞에 `--` 를 두며, (c) 경로가 필요하면 고정 접두를 템플릿에 두거나(`..` 는 막지 못한다) script 도구에서 검증하고, (d) 민감 경로를 읽을 수 있는 프로그램을 도구로 등록하지 않는 것이다. 필요가 구체화되면 별도 태스크에서 `x-forge-path` 를 설계한다(위 한계를 문서화한 채로).

**5. 사소한 결함(AC-4)**: (a) `forge tool add --help` 의 `--allow-var-subcommand` 설명이 백틱(`cat -- {{file}}`)을 값 이름으로 해석해 플래그 줄이 깨지던 것을 작은따옴표로 고쳤다(시험 `TestToolAddHelpFlagNamesAreNotBroken`). (b) Run 단계의 중복 deny 검사를 덮는 TOCTOU 시험 `TestRunStageRechecksDenyListAfterBinarySwap`(등록 때 무해했던 바이너리를 env 링크로 교체: 등록 시점 조회에 보이지 않는 경우, dry-run, 첫 검사 뒤 환경 구성 중에 교체하는 경우; exec 직전 재검사와 dry-run 의 첫 검사는 변이로 제거하면 각각 실패, Run 경로의 첫 검사는 중복이라 단독으로는 잡히지 않음). (c) https→http 리다이렉트를 TLS 목 서버로 시험 `TestHTTPSToHTTPRedirectOverTLS`(기본은 거부되고 평문 서버에 접속하지 않음, `--allow-http` 로 허용돼도 정의 헤더(시크릿)는 http 홉에 전달되지 않음). 시험 전용 `testTLSConfig` 훅(비공개 변수, 프로덕션 nil)을 `internal/tool/http.go` 에 추가했다.

**6. 설치 미리보기의 스크립트 내용(AC-5, TASK-0025 AC-1 이월 포함)**

- **표시 순서**: 실행 가능한 파일(실행 비트·셔뱅·스크립트 확장자)을 경로 사전순이 아니라 **위험도 순**으로 정렬해 상위 30개를 보이고 나머지는 개수(`executables_more`)만 표시한다. 점수: 위험 패턴(있으면 100 + 10×종류 수) > 실행 비트(4) > 셔뱅(2) > 확장자만(1), 같으면 경로 사전순. 위험 패턴이 있는 실행 파일의 전체 개수는 `executables_risky` 와 경고문에 나온다(31번째 이후에 둔 위험 스크립트도 위로 올라온다). 시험 `TestPreviewRiskyScriptBeyondTheLimitIsShownFirst`, `TestPreviewExecutablesAreOrderedByRisk`.
- **내용 요약**: 텍스트 파일(바이너리 판정 제외)의 **앞 64KiB** 에 위험 패턴 정규식을 적용해 종류만 보여 준다(`risk_patterns`): SKILL.md 와 같은 목록(curl, wget, `| sh`, eval, `base64 -d`, `chmod +x`, `rm -rf`, sudo, ssh, nc)에 스크립트용 패턴(네트워크 호출 API, `os.system`·`subprocess`·`child_process` 같은 프로세스 실행, `~/.ssh`·`.aws`·`.env` 같은 자격 증명 파일 접근)을 더했다. **휴리스틱이며 안전 판정이 아니다**(난독화·분할·인코딩·다른 파일 `source` 는 놓친다). **스크립트 앞부분에 NUL 바이트가 있으면 바이너리로 분류되어 위험 패턴 검사와 첫 줄 표시를 건너뛴다**("텍스트가 아닌 파일" 경고에는 나온다).
- **첫 줄**: 위험도 상위 **5개** 파일의 **첫 10줄**을 `head` 로 보인다(`head_more` 는 더 있음을 뜻함). 줄은 `textsafe` 로 정화(제어·방향·제로폭 문자는 `\x1b`, `\u202e` 같은 보이는 이스케이프)하고 줄당 160바이트로 자른다. 모든 파일의 첫 줄을 보이지 않는 이유는 출력 폭주 방지다.
- **출력 호환**: `forge skill add --preview --json` 의 `schema` 는 1 그대로이고, 기존 필드는 모두 유지된 채 `executables[].risk_patterns`·`head`·`head_more` 와 최상위 `executables_risky` 가 **추가**됐다(없으면 생략). 텍스트 출력은 기존 줄 형식에 하위 줄(`위험 패턴:`, ` N| <줄>`)이 붙는다. 안내 문구(`HeuristicNote`, 경고문)는 "스크립트 내용은 검사하지 않음" 에서 "일부를 휴리스틱으로 검사" 로 바뀌었다.
- **한계**: 전체 파일을 읽지 않는다(앞 64KiB, 첫 10줄). 첫 줄이 무해해도 아래에 악성 코드가 있을 수 있다. 실행 가능하지 않은 파일(문서·데이터)은 내용을 검사하지 않는다. 설치 후 모델이 스크립트를 실행하는 것은 클라이언트의 승인에 달려 있다(S5).

## 5. 사용자가 해야 할 일 (체크리스트)

1. **설치 전에 미리보기를 읽는다.** `forge skill add --preview <소스>`, `forge mcp add --preview ...` 는 아무것도 설치·등록하지 않는다. 특히 `hooks`, `allowed-tools`, 실행 가능한 파일, `npx -y`·`@latest`, 평문 http, 사설 IP 경고를 본다.
2. **해시를 고정한다.** 미리보기의 `트리 sha256` 을 `--sha256` 으로, git 은 `--ref <40자 커밋>` 으로 고정한다. 정기적으로 `forge skill check`(로컬 변조 탐지)와 필요할 때 `forge skill check --fetch` · `forge skill update <이름>`(변경 요약 확인 후 승인)을 쓴다.
3. **MCP 도구 정의를 승인하고 필요하면 고정한다.** `forge mcp refresh` 후 `forge mcp show <이름>` 으로 설명을 읽고 `forge mcp approve <이름>`. 신뢰하는 서버에는 게이트웨이 노출과 `forge mcp pin <이름> --enforce` 를 고려한다. 변경 경고가 나오면 바뀐 설명을 먼저 읽는다.
4. **비밀은 `${ENV}` 참조로만** 넣는다(`--env KEY='${KEY}'`, `--header 'Authorization=${TOKEN}'`). 값을 명령줄·설정 파일에 직접 쓰지 않는다. 서버에 필요한 변수만 선언한다.
5. **`forge doctor` 를 주기적으로 실행한다.** 스킬 저장소 변조(`security.skills`), 승인된 정의와 다른 MCP 도구(`security.mcp`), 백업 권한·개수, 설정 파일 권한을 본다.
6. **신뢰할 수 없는 저장소에서는 `forge sync --apply` 전에 `--dry-run --diff` 를 확인한다.** 낯선 저장소의 `.mcp.json`·`.claude/settings.json` 은 클라이언트가 명령을 실행할 수 있는 파일이다.
7. **`confirm=ask` 가 필요한 도구는 elicitation 을 지원하는 클라이언트에서 쓴다.** 코드 실행형 바이너리(`sqlite3`, `npm`, `uv`, `go run` 등)를 도구로 등록하면 `risk=code-exec` 경고가 나오고 게이트웨이는 호출마다 확인을 요구한다. `--confirm none --yes-code-exec` 는 인자가 코드로 해석될 수 있음을 이해한 도구에만 쓴다. deny 목록이 샌드박스가 아님을 기억한다.
8. `~/.forge` 와 `$FORGE_HOME` 은 본인만 쓰게 둔다(권한 0700). 이 디렉터리에 쓰는 다른 프로세스는 신뢰 경계 안에 있다.

## 6. 이번 태스크에서 추가된 명령 요약

| 명령 | 요약 |
|------|------|
| `forge skill add [--preview] [--yes] [--strict-local] [--sha256 H] [--ref R] [--json] <소스>` | 미리보기(stderr) 출력. git/zip 은 승인 필수(터미널 y/N 또는 `--yes`, 아니면 거부·종료 코드 1). 로컬 디렉터리는 질문 없음(`--strict-local` 로 승인 필수) |
| `forge skill update <이름> [--yes]` | 기록된 소스를 다시 가져와 변경 요약 후 승인 시 새 불변 버전 추가 |
| `forge skill check [<이름>] [--fetch] [--json]` | 읽기 전용. 설치 파일 해시 vs 기록된 `content_hash`(변조 탐지). `--fetch` 일 때만 원본(네트워크) 비교 |
| `forge mcp add [--preview] [--strict] [--yes] ...` | 등록 전 미리보기. 기본은 질문 없음 |
| `forge mcp approve <이름> [--tool 도구]...` | 현재 캐시된 도구 정의를 승인(해시·정의·시각 저장) |
| `forge mcp pin <이름> --enforce\|--no-enforce` | 게이트웨이가 승인된 정의와 같은 도구만 노출(기본 꺼짐) |
| `forge doctor` | `security.skills`, `security.mcp`, `security.mcp.unapproved`, `security.mcp.enforce` 점검 추가 |

저장 형식: 스킬 `skill_versions.source_ref` 는 `--ref` 를 준 경우 `<요청 ref>@<커밋>`, 아니면 커밋 해시(기존 의미 유지). 승인 기록은 마이그레이션 `0002_mcp_tool_approvals.sql` 의 `mcp_tool_approvals` 테이블, enforce 는 `settings` 키 `mcp.enforce.<서버>`. `db/schema.sql` 은 이제 모든 마이그레이션을 번호 순으로 이어 붙인 스냅샷이다(`make check-schema`).

- **스킬 설치 승인 해시, 읽기 전용 열기 폴백(TASK-0032 AC-6)**: 레지스트리를 읽기 전용으로 못 열어(미반영 WAL 등) 읽기·쓰기 열기로 폴백한 `forge skill add` 도, 그리고 `forge skill update` 도 승인 후 `Restage` 로 스테이징을 새 디렉터리로 옮기며 승인한 해시와 비교한다(교체된 스테이징은 거부, 이후 `Registry.Add` 도 같은 해시를 요구; 시험은 승인 직후 스테이징을 바꾸는 테스트 전용 훅으로 폴백 `add` 와 `update` 모두 검증). 남은 한계: `Restage` 후 `Add` 가 복사하기까지의 짧은 구간과 같은 사용자 권한의 공격자는 막지 못한다.
